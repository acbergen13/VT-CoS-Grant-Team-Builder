and builds explainable VT College of Science faculty teams via a RAG chatbot.

## Non-negotiable constraints (easy to violate)
- Faculty ranking is deterministic: score = 0.6×semantic-similarity +
  0.25×normalized H5-index + 0.15×normalized citation count. Weights live in a
  config file and must never be set or changed by the LLM.
- Fixed role list: Principal Investigator, Co-PI, Methods/Technical Lead,
  Domain Expert, Data/Computational Specialist, Project Coordinator. Every team
  needs ≥1 PI plus ≥1 additional role; max one role per person.
- grants.gov: `POST https://api.grants.gov/v1/api/search2` with
  `oppStatuses: "forecasted|posted"` (no auth). Closed solicitations are
  archived locally, never shown. Details come from `fetchOpportunity` — the
  documented endpoint 502s (proxy down, Oct 20); the client falls back to its
  backend `POST https://apply07.grants.gov/grantsws/rest/opportunity/details`
  (form-encoded `oppId`), which works. Schemas pinned in
  `gt/grants/client.py`.
- LLM: VT ARC endpoint `https://llm-api.arc.vt.edu/api/v1`, OpenAI-compatible
  schema; spec default model `vt-arc-llm`. Current `.env`/live gates and
  `.env.example` use `gpt-oss-120b`. Thinking models can spend
  `max_output_tokens` on hidden reasoning and return empty content with
  `finish_reason=length` — raise the budget or use `gpt-oss-120b`. All
  keys/base URLs in `.env`, never hardcoded, never committed:
  `VT_ARC_API_KEY`, `VT_ARC_BASE_URL`, `VT_ARC_MODEL`. Elsevier API key
  (production mode) also lives in `.env`; entitled content requires campus
  network.
- LLM team builds are a fixed workflow, not agent-decided: **3 calls per
  build** (keyword extraction, per-role focuses, batched rationales); a revise
  turn is 2. Membership is greedy assignment in code; roles are the fixed
  `team.base_roles`; the retrieval query is code-assembled by
  `gt/llm/optimize.py:canonical_query` (anchor + sorted LLM keywords); the
  critique scope guard is in `gt/llm/team.py`. The disk cache
  (`data/llm_cache/`, `CACHE_FORMAT = "v3"`) pins the plan + finished build;
  a cache hit is bit-identical with **0 LLM calls**. Degraded fallback output
  is never cached; bump `CACHE_FORMAT` when changing cached shapes.
- Reproducibility is graded, with a two-tier contract (`plan.md` decision 10):
  cache hit → bit-identical team + 0 LLM calls; cache-cleared regeneration →
  same role structure and people overlap ≥ n−2 (endpoint keyword drift is
  accepted). Chain-of-verification is pure code (`gt/llm/verify.py`): reject
  wrong Scopus IDs, invented EIDs, and empty rationales; never trust the LLM
  for membership or ordering.
- Two Streamlit views share session state: browser hands a structured
  solicitation object to the chatbot with no re-fetch or data loss.
  `app/chat.py` auto-builds the first team, caches the pipeline/ARC
  client/builder in session state, and keeps the existing team when the same
  solicitation is reopened; a different solicitation resets the conversation.
- Retrieval entrypoint is `gt/retrieval/pipeline.py:build_pipeline`:
  hybrid BM25+vector recall fused by RRF (k=60), then author-level grouping
  + MMR (λ=0.7, config `retrieval.mmr_lambda`) — MMR decides POOL MEMBERSHIP
  only; the deterministic RosterScorer decides ORDER. Vector index: ChromaDB
  at `data/chroma/` (19,461 chunks, one per CoS author × publication),
  embedder `BAAI/bge-small-en-v1.5` (first use downloads ~130MB from HF;
  queries need the BGE `Represent this sentence...` prefix). Rebuild
  deliberately via `python scripts/build_index.py`; the pipeline auto-builds
  only when the index is empty or the manifest is out of sync with the corpus
  — never inside a chat turn. All tie-breaks are `(-score, scopus_id)`:
  reruns are bit-identical (warm query ~0.03s).

## Data
- `data/authors.csv` — 501 rows, ~500 CoS faculty after dedupe; join key
  `Scopus ID`; metrics include H-Index, H5 Index, Citation Count. One ID is
  shared by two people (56940337900: Iliescu kept, Driscoll dropped —
  keep-first-by-file-order rule in `gt/faculty/roster.py`).
- `data/publications.csv` — ~21.5k rows, 51MB, starts with a UTF-8 BOM: parse
  with `encoding="utf-8-sig"` or joins/sorting silently break. Links to authors
  via `Author(s) ID` (semicolon-separated Scopus IDs). With dtype=str pandas,
  empty cells are float NaN — use the `_clean_str` helpers, since `NaN or ""`
  yields the literal string "nan".
- Dev reads these CSVs; production must use the Elsevier API behind the same
  retrieval interface (`gt/faculty/source.py`), with local caching to limit
  repeat calls. `ElsevierFacultySource` is still a `NotImplementedError`
  placeholder — keep `data_source: csv` in `config/settings.yaml` until
  Stage 6.
- `data/*.csv` stay out of git (`publications.csv` is 51MB); data ships only in
  the submission zip. `data/chroma/` and `data/llm_cache/` are local
  artifacts (also gitignored); the cache is content-keyed and safe to ship.
